# Security Specification — Ruta Inducción SENA

## 1. Data Invariants & Master Source of Truth

1. **Verified Authentication Gate**: Every read and write requires an authenticated user with `request.auth.token.email_verified == true`. Unverified emails cannot read, write, or claim bootstrap admin privileges.
2. **PII Split Isolation (`/users_private/{userId}`)**: Email addresses are strictly isolated inside `/users_private/{userId}`. Only the owner (`request.auth.uid == userId`) or a verified admin can `get` this document; `list`, `update`, and `delete` are unconditionally denied. Academic collections (`fichas`, `enrollments`, `evaluations`) store zero PII.
3. **Master Gate Relational Sync (`/fichas/{fichaId}/enrollments/{enrollmentId}`)**: Every enrollment belongs to a parent `/fichas/{fichaId}` document. Single-document reads and writes fetch `/fichas/$(fichaId)` via `get()`. If a Ficha does not exist or is closed (`status == 'cerrada'`), enrollment creation and non-admin updates are synchronously blocked. On creation, `incoming().instructorId` MUST equal the parent Ficha's `instructorId`.
4. **Tiered Identity & Action-Based Updates**:
   - **Tier 1 (Ficha Instructor)**: May update `appropriationState` (including `'certificado'` only when `evalScore >= 70`) and `instructorObservation` via strict `affectedKeys().hasOnly(...)`.
   - **Tier 2 (Apprentice / `authorId`)**: May update `completedModules` or submit evaluation metrics (`evalScore`, `dimIdentity`, `dimValues`, `dimRights`, `dimDuties`, `attemptsCount`, `appropriationState` restricted to `'en_proceso' | 'apropiado' | 'plan_mejoramiento'`), never self-certifying `'certificado'` and never editing `instructorObservation`.
5. **Terminal State Locking**: Once a Ficha reaches `status == 'cerrada'` or an Enrollment reaches `appropriationState == 'certificado'`, all non-admin updates are permanently rejected.
6. **Immutable Audit Logs (`/evaluations/{evalId}`)**: Evaluation attempts verify existence and active status of `fichaId` and match `instructorId` to the parent Ficha on `create`, enforce `passed == (score >= 70)`, and deny all `update` and `delete` operations.
7. **Zero-Blanket Secure List Queries & Cost Guard**: Every `allow list` rule enforces `resource.data` ownership/visibility boundaries without calling `get()` or `exists()`.
8. **Owner-Isolated Apprentice Profile (`/apprentice_profiles/{userId}`)**: Stores non-PII institutional characterization (`apprenticeName`, `documentCode`, `trainingLevel`, `modality`, `regionalCenter`, `bloodType`, `preferredProductiveAlt`, `representationRole`, `differentialFocus`, `commitmentAccepted`, `bioGoal`, `selectedFichaId`). Strictly restricted to owner (`request.auth.uid == userId`) or verified admin on `get`; `list` and `delete` are unconditionally denied; `create` and `update` enforce `isValidApprenticeProfile()`, immutable `userId` and `createdAt`, `request.time` temporal integrity, and strict `affectedKeys().hasOnly(...)`.
9. **Formato GFPI-F-165 Productive Stage Selection (`/gfpi_f_165_submissions/{userId}`)**: Stores official GFPI-F-165 filing and contact fields (`contactEmail`, `contactPhone`, `residenceAddress`, `companyContactName`) protected under Ley 1581 de 2012. Enforces `isValidGfpiF165Submission(incoming(), userId)` on both `create` and `update`, requires `apprenticeSignatureAccepted == true` whenever `status == 'radicado'`, validates `fichaId` existence and matches `instructorId` to `/fichas/$(fichaId)` via Master Gate when `fichaId != ''`, locks non-admin mutations once `status == 'validado_coordinacion'`, restricts `get` strictly to owner, parent Ficha instructor, or admin (zero cross-apprentice PII exposure), and restricts `list` strictly via `resource.data` without DB lookups.
10. **Instructor-Isolated Google Sheets Link (`/ficha_sheet_links/{fichaId}`)**: Stores the linked Google Drive `spreadsheetId`, `spreadsheetUrl`, `spreadsheetTitle`, `templateSourceName`, `lastSyncedRows`, and `lastDataSignature` for a SENA Ficha. Apprentices have zero read or list access (`allow list: if false`); `get`, `create`, and `update` verify via Master Gate `get(/databases/$(database)/documents/fichas/$(fichaId))` that the requester is the parent Ficha's `instructorId` or a verified admin.
11. **Strict Apprentice vs. Instructor Role Isolation (`/fichas/{fichaId}` & `/admins/{adminId}`)**: Only verified authorized instructors/administrators (`isAdmin()`) may create `/fichas/{fichaId}` documents, preventing any apprentice from creating a Ficha or escalating themselves to `instructorId`. Furthermore, non-admin apprentices creating an enrollment under `/fichas/{fichaId}/enrollments/{enrollmentId}` are strictly restricted to their single canonical document ID (`enrollmentId == 'enr_' + request.auth.uid`) with `instructorObservation == ''`.

## 2. The "Dirty Dozen" Adversarial Payloads

1. **Payload 1 — Shadow Field Injection on Ficha or GFPI-F-165 Create**: Valid `Ficha` or `GfpiF165Submission` payload plus `"isVerified": true` -> Rejected by `data.keys().hasOnly(...)`.
2. **Payload 2 — Email Spoofing on Bootstrap Admin**: Authenticated token with `email: "enithmenco@gmail.com"` and `email_verified: false` attempting admin write -> Rejected by `request.auth.token.email_verified == true`.
3. **Payload 3 — PII / Profile Blanket Scrape**: Verified user `uid_b` calling `get` on `/users_private/uid_a`, `/apprentice_profiles/uid_a`, or unshared `/gfpi_f_165_submissions/uid_a` -> Rejected by owner/instructor/admin gate.
4. **Payload 4 — Identity Spoofing on Enrollment, Profile, or GFPI-F-165 Create**: Verified user `uid_attacker` creating `/fichas/ficha_1/enrollments/enr_1` with `authorId: "uid_victim"` or `/gfpi_f_165_submissions/uid_victim` -> Rejected by `request.auth.uid` identity check.
5. **Payload 5 — Instructor Hijack on Enrollment or GFPI-F-165 Create**: Apprentice linking `ficha_1` while setting `instructorId: "uid_accomplice"` instead of the parent Ficha's `instructorId` -> Rejected by Master Gate `incoming().instructorId == parentFicha.instructorId`.
6. **Payload 6 — Orphaned Evaluation or GFPI-F-165 Write**: Creating `/evaluations/eval_1` or `/gfpi_f_165_submissions/uid_1` referencing nonexistent `fichaId: "ghost_ficha"` -> Rejected by `exists(/databases/$(database)/documents/fichas/$(incoming().fichaId))`.
7. **Payload 7 — Self-Certification / Unsigned Radicación State Shortcut**: Apprentice updating enrollment `appropriationState` to `"certificado"`, setting GFPI-F-165 `status` to `"validado_coordinacion"`, or setting `status: "radicado"` with `apprenticeSignatureAccepted: false` -> Rejected by Tier 2 state & signature gates.
8. **Payload 8 — Terminal State Re-Opening**: Non-admin attempting to modify an enrollment with `appropriationState == "certificado"`, a Ficha with `status == "cerrada"`, or a GFPI-F-165 submission with `status == "validado_coordinacion"` -> Rejected by Terminal State Lock.
9. **Payload 9 — Resource / ID Poisoning (Denial of Wallet)**: Creating a document with a 500-character ID, a 10KB `instructorObservation`, or a 5KB `alternativeJustification` in `/gfpi_f_165_submissions/{userId}` -> Rejected by `isValidId()` and `.size() <= 400`.
10. **Payload 10 — Array / Enum / Date Regex Poisoning**: Updating `completedModules` with `["hacked_module"]`, `selectedAlternative: "Invalid Alt"`, or `lectivaStartDate: "2026/99/99"` in `/gfpi_f_165_submissions/{userId}` -> Rejected by `.hasOnly(...)`, enum allowlists, and `^\\d{4}-\\d{2}-\\d{2}$`.
11. **Payload 11 — Forged Client Timestamp / Immortal Field Mutation**: Updating `createdAt` or `userId` in `/apprentice_profiles/{userId}` or `/gfpi_f_165_submissions/{userId}`, or passing a client timestamp for `updatedAt` -> Rejected by `incoming().createdAt == existing().createdAt`, `incoming().userId == existing().userId`, and `incoming().updatedAt == request.time`.
12. **Payload 12 — Unauthorized List Query Scraping**: Verified user querying `collection(db, 'evaluations')` or `collection(db, 'gfpi_f_165_submissions')` without ownership/instructor filter -> Rejected by `allow list` rules checking `resource.data`.
